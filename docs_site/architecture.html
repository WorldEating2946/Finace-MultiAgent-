系统架构设计

六层架构：API 层 → Runtime 层 → Agent 层 → RAG 层 → 向量存储层 → 基础设施。依赖方向严格单向，上层调用下层，各层通过 services 业务编排串接。

一个研究请求的完整旅程

用户请求→ POST /research/start→ Redis 队列→ Worker 认领(CAS)→ 意图理解→ 计划生成→ 画像 + 逐步证据检索→ LLM 报告合成→ 质量评测→ Atomic Finalize

部署拓扑（生产）

Client→ FastAPI 网关（无状态，可水平扩展）
Worker Pool ×N↔Redis（队列/AOF） ↔PostgreSQL（状态/租约/checkpoint/报告） →Milvus（向量） →LLM API

架构不可变规则

规则说明
Agent 不触碰基础设施Agent 中禁止写 SQL / 调接口 / 管理数据库连接，一律经 services/tools 封装。
LLM 不负责精确计算结构化数据走 Tool + Python 计算；LLM 只做理解、规划、文本生成。
State 必须可序列化TypedDict 管理 Workflow State，可追踪、可序列化、可恢复。
Agent 职责单一Research Agent 只做企业知识研究与证据检索，不越界做财务计算/舆情抓取。
