RAG 检索链路

数据分类施策：非结构化知识 → RAG；结构化数据 → Tool；实时舆情 → Search。离线入库 + 在线检索双链路，Dense+Sparse → RRF 融合 → CrossEncoder 精排。

① 离线入库链路（知识库构建）

1
文档解析PDF outline（fitz.get_toc）优先恢复章节结构 · OCR 兜底扫描版
2
智能切片章节感知 + 重叠窗口 + 元数据（章节/页码/公司/来源类型）
3
向量化BGE-M3（CUDA）→ Dense 向量 + Sparse 词权重
4
写入向量库VectorStore.add() → FAISS 或 Milvus
5
元数据关联company / source_type / section / page 随 chunk 落库

幂等与更新

  • chunk_id = MD5(document_id + index + 内容前缀)，重复入库不重复插入
  • 文档更新先删后插（按 document_id），无残留旧数据
  • company 第一级过滤，切片不跨企业混排

可溯源

  • 每个 chunk 携带 source_name（如"年报 > 第3章 > 3.1"）
  • 入库与查询共用同一 Embedding 模型，禁止版本漂移
  • PR44 迁移工具：FAISS→Milvus 幂等 + 分批 + 对账 + 回滚

② 在线检索链路（Hybrid RAG）

1
Query Rewrite规则同义词 + LLM 改写（消歧、扩展专业术语）· 配置 RAG_QUERY_REWRITER
2
Dense RetrievalBGE-M3 编码 → 向量 Top-K（公司 scalar filter 隔离）
3
Sparse RetrievalBM25 词权重 Top-K（与 Dense 并行）
4
RRF 融合Reciprocal Rank Fusion：dense/sparse 排名合并，对分数尺度差异鲁棒
5
精排CrossEncoder（bge-reranker-v2-m3）对 Top-N 重排 · Metadata-aware Rerank 加权
6
置信度兜底Top-1 confidence < 0.75 → 显式降级（Web Search / 明示不足），禁止 LLM 凭记忆硬答
# 唯一入口契约：Agent 只提供问题 + 公司，不感知底层向量库 from app.rag import retrieve result = retrieve(query, company="小鹏汽车", top_k=5)

③ 向量存储层（PR44）

FAISS（默认）

  • 本地开发 / 离线评测 / 紧急回滚
  • 零服务依赖，可落盘存档 data/vector_store/

Milvus（生产）

  • finance_agent 库 · FLAT/COSINE · 多公司 scalar filter
  • 与 FAISS 检索结果逐项精度一致，延迟仅高 6~9%
RAG_VECTOR_BACKEND=faiss # 或 milvus # 启动时对所选后端做健康检查 fail-fast，后端不可用则拒绝启动

关键工程决策

决策原因 / 收益
PDF outline 优先 TOCOCR 直接切分丢失章节结构 → 小米 Recall@5 10% → 70%
Query Rewrite规则同义词 + LLM 改写 → 小米 Recall 70% → 80%
RRF 融合对 dense/sparse 分数尺度差异鲁棒，优于加权和
公司 scalar filter多公司知识库隔离，检索不跨公司串扰
BGE-M3 双路单模型覆盖 Dense+Sparse，避免两套嵌入维护
