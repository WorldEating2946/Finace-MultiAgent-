生产级 Runtime

四个组件分工，各司其职、互不为对方兜底：Redis = 调度，PG Lease = 所有权，Checkpoint = 恢复，Report = 产物。故障矩阵全覆盖，任务可崩溃恢复、可水平扩展。

四组件分工

Redis · 调度

"这个任务需要被执行"——list 队列（RPUSH/BLPOP），Worker 取到后必须再走 PG CAS 认领才能执行。AOF 持久化，重启丢队列 ≤1s。

PostgreSQL · 状态事实

research_tasks 是唯一状态真相（queued/running/paused/completed/failed/rejected/cancelled + 租约列）。Redis 只是提示，PG 说了算。

Checkpoint · 恢复

LangGraph checkpoint（thread_id）存执行中间态；崩溃/重启后 aresume 幂等续跑，不从头执行。

Report · 产物

research_reports 落最终报告快照（upsert），与终态单事务原子提交——运行时状态 ≠ 业务产物。

状态机

queued ─claim(CAS)─▶ running ─▶ completed ─原子快照─▶ research_reports
running ─▶ failed　　running ─人工审核─▶ paused ─resume─▶ running
running/queued ─cancel─▶ cancelled　　paused ─reject─▶ rejected

认领路径（一条 SQL 三种来源）

status='queued' → running （新任务） status='running' AND 心跳过期(>lease_ttl) → running （崩溃接管，attempts+1） status='paused' → running （人工审核后 resume）
